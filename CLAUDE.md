# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Browser Arkanoid/Breakout game in plain HTML, CSS and JavaScript with **zero dependencies** (no npm, no bundler, no build step, no test framework). The README, specs, UI text and code comments are in Spanish.

## Running

No build. Open `index.html` directly (`file://` works) or serve the repo root with any static server (e.g. `python3 -m http.server`). Append `?level=N` (1–10) to start at level N.

There are no automated tests. Each implementation step is verified manually in the browser, as the spec's plan describes.

## Code layout

All files are classic scripts (no ES modules, so `file://` keeps working) that share globals. Load order in `index.html` matters:

1. `assets/spritesheet.js`: sprite data and draw helpers (see below).
2. `levels.js`: `MAX_LEVEL`, `levelRows(level)`, `ballSpeed(level)`, `createLevelBricks(level)`. Levels are generated by a deterministic formula, not hand-made.
3. `game.js`: constants, a single `state` object, input, update, render and the `requestAnimationFrame` loop.

`game.js` conventions:

- All mutable data lives in `state`. `state.phase` drives the game: `'serve' | 'playing' | 'paused' | 'levelClear' | 'won' | 'lost'`. `paused` remembers `pausedFrom` to resume.
- Movement is `dt`-based (px/s), with `dt` clamped to `MAX_DT = 1/30` to avoid tunneling.
- Fixed 800×600 canvas. Overlays (pause, level clear, victory, game over) are the HTML `#overlay` div, not canvas drawing. The HUD is drawn on the canvas.
- Input: keyboard (←/→, A/D, Space, P/Esc), mouse and touch buttons (`#left-button`, `#right-button`, `#action-button`, `#pause-button`). `primaryAction()` is the shared "launch / continue / restart" action.
- Style: spaces inside parentheses and brackets (`fn( a, b )`, `[ 'a', 'b' ]`), named constants in `UPPER_SNAKE_CASE` with a short trailing comment when the value isn't obvious.

## Assets (`assets/`)

- `spritesheet.js` defines globals:
  - `SPRITES`: source rects (`sx, sy, sw, sh`) for `paddle`, `ball`, and `blocks.<color>`. Colors: gray, red, yellow, cyan, magenta, hotpink, green.
  - `EXPLOSION_FRAMES.<color>`: 4-frame brick-break animation per color. `EXPLOSION_DURATION = 150` (ms).
  - `loadSpritesheet(cb)`: loads the image once and queues callbacks until it is ready.
  - `drawSprite(ctx, name, x, y, w, h)`: `name` is `'paddle'`, `'ball'`, or `'block_<color>'`.
  - `drawFrame(ctx, frame, x, y, w, h)`: draws one explosion frame.
  - Both draw functions do nothing until the sheet has loaded.
- The spritesheet path is hardcoded as `'assets/spritesheet-breakout.png'`, relative to the page, so the HTML entry page must stay at the repo root.
- `sounds/ball-bounce.mp3` (walls, paddle) and `sounds/break-sound.mp3` (brick).

## Workflow: spec-driven development

Every feature starts as a spec. No code is written without an approved spec.

### Skills

Project skills live in `.agents/skills/` (symlinked from `.claude/skills/`), installed from `Klerith/fernando-skills` via `skills-lock.json`. `.agents/` is gitignored, so a fresh clone must reinstall them from the lock file.

- `/spec <description>`: asks clarifying questions, then writes `specs/NN-slug.md` in `Borrador` state. Never writes code. Follows `.agents/skills/spec/template.md`.
- `/spec-impl <NN-slug>`: runs only on `Aprobado` specs. Requires a clean working tree. Creates or switches to branch `spec-NN-slug` (auto if `AutoCreateBranch: true` in `specs/.spec-config.yml`). Implements the plan one step at a time, pausing for diff review after each step. Never commits automatically.

### Spec files (`specs/`)

- Name: `NN-slug.md`, two-digit sequential number and a Spanish kebab-case slug (`01-mvp-jugable.md`, `02-diez-niveles.md`). Next spec is `03`.
- Written in Spanish. Header and section headings must match existing specs exactly:

```markdown
# SPEC NN — Título corto

> **Status:** Borrador
> **Depends on:** SPEC 01   (or —)
> **Date:** YYYY-MM-DD
> **Objective:** Una sola frase.

## Alcance            (**Dentro:** / **Fuera de alcance (para futuras specs):**)
## Modelo de datos    (constants, state shape, function signatures; short snippets only)
## Plan de implementación   (numbered steps, each ending with "Prueba manual: …")
## Criterios de aceptación  (checkbox list)
## Decisiones         (**Sí:** / **No:** bullets, one reason each)
## Riesgos            (table: Riesgo | Mitigación)
## Lo que **no** está en esta spec
```

- Status values (Spanish set): `Borrador` → `En revisión` → `Aprobado` → `Implementado` (or `Obsoleto`). **Only the human changes the status**; the agent never sets `Aprobado` or `Implementado`.
- One sentence per idea, concrete names (files, keys, constants), no TODOs, no full functions.
- Anything outside the current spec's scope goes into a future spec, not into the code.

### Git

- `main` is the default branch. Feature work happens on `spec-NN-slug` branches.
- Commit messages use Conventional Commits (`feat:`, `docs:`, `chore:`).
- Commit only when the user asks.
